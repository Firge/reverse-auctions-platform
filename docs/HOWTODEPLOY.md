# Инструкция по деплою

Этот документ описывает, как развернуть проект, настроить домен, SSL через Certbot и автоматический деплой из GitHub.

## 1) Требования к серверу

- Ubuntu 22.04+ (или аналог)
- Публичный IP-адрес
- Открытые порты: 80 (HTTP), 443 (HTTPS)
- Установлены Docker и Docker Compose

Установка Docker (пример для Ubuntu):

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker
```

## 2) Настройка домена

1) Купите домен (пример: `coursework-hse.ru`).
2) В панели DNS создайте записи `A`, указывающие на публичный IP сервера:
  - `@` -> `YOUR_SERVER_IP`
  - `www` -> `YOUR_SERVER_IP` (опционально)
3) Дождитесь обновления DNS (может занять от минут до часов).

## 3) Клонирование и настройка проекта на сервере

```bash
sudo mkdir -p /opt/bidfall
sudo chown $USER:$USER /opt/bidfall
cd /opt/bidfall
git clone <YOUR_REPO_URL> .
```

### Секреты и переменные окружения

Создайте файл `.env` на сервере. Пример (адаптируйте под свой проект):

```bash
cd /opt/bidfall
cat > .env << 'EOF'
DJANGO_SECRET_KEY=change-me
DJANGO_DEBUG=false
ALLOWED_HOSTS=coursework-hse.ru,www.coursework-hse.ru
POSTGRES_DB=bidfall
POSTGRES_USER=bidfall
POSTGRES_PASSWORD=change-me
EOF
```

Если вы используете отдельные env-файлы для backend/frontend, разместите их рядом с соответствующим `docker-compose` файлом или обновите compose, чтобы он ссылался на них.

## 4) Запуск сервисов (ручной деплой)

Используйте существующие docker compose файлы в репозитории:

```bash
cd /opt/bidfall
docker compose -f docker-compose.yaml up -d --build
```

## 5) Nginx + проксирование домена

Установите Nginx:

```bash
sudo apt install -y nginx
```

Создайте конфиг сайта `/etc/nginx/sites-available/bidfall` и активируйте его:

```bash
sudo ln -s /etc/nginx/sites-available/bidfall /etc/nginx/sites-enabled/bidfall
sudo nginx -t
sudo systemctl reload nginx
```

## 6) SSL через Certbot

Установите Certbot и плагин для Nginx:

```bash
sudo apt install -y certbot python3-certbot-nginx
```

Выпустите сертификаты и автоматически настройте Nginx:

```bash
sudo certbot --nginx -d coursework-hse.ru -d www.coursework-hse.ru
```

Продление происходит автоматически через systemd timers. Проверка:

```bash
sudo certbot renew --dry-run
```

## 7) Деплой через GitHub Actions (CI/CD)

### Использование текущих пайплайнов

В репозитории уже есть два workflow-файла:

- `.github/workflows/docker-image.yml` — собирает и публикует Docker-образы в GitHub Container Registry (GHCR) при изменениях в сервисах.
- `.github/workflows/deploy-prod.yml` — деплоит на сервер после успешной сборки, либо вручную через `workflow_dispatch`.

#### Как работает сборка образов

Workflow `Build and Push Docker Artifacts` автоматически запускается при `push` и `pull_request` в ветку `main`.
Он определяет, какие сервисы изменились, и собирает только их образы.

#### Как работает деплой

Workflow `Deploy To Production` запускается:

- автоматически, когда сборка образов завершилась успешно для `main`,
- вручную из GitHub Actions (через `Run workflow`).

При ручном запуске доступны параметры:

- `image_tag` — тег образов (например, `latest` или SHA коммита)
- `services` — `auto`, `all` или CSV список (`backend,frontend,tools,smtp-worker,smtp-relay`)
- `run_init_catalog` — принудительный запуск инициализации каталога

### Добавление секретов в GitHub

В вашем репозитории GitHub:

`Settings -> Secrets and variables -> Actions -> New repository secret`

Секреты, которые используются текущими пайплайнами:

- `VPS_HOST` - IP-адрес или хост сервера
- `VPS_USER` - пользователь SSH
- `VPS_SSH_KEY` - приватный ключ для деплой-пользователя
- `VPS_DEPLOY_PATH` - путь до каталога проекта на сервере (например, `/opt/bidfall`)
- `VPS_ENV_PROD_PATH` - путь до файла `.env.prod` на сервере (например, `/opt/bidfall/env/.env.prod`)

Дополнительно (если нужно):

- Любые переменные, которые вы помещаете в `.env.prod` (настраиваются на сервере, а не в Actions).
- По умолчанию для доступа к GHCR используется `GITHUB_TOKEN`, он уже доступен в Actions.

Адаптируйте `.env.prod` и пути под вашу инфраструктуру.

## 8) Настройка отправки писем

Проект поддерживает отправку писем по SMTP. Добавьте SMTP-настройки в `.env` (или env-файл backend):

```bash
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your-user@example.com
SMTP_PASSWORD=change-me
SMTP_USE_TLS=true
DEFAULT_FROM_EMAIL=Bidfall <no-reply@coursework-hse.ru>
```

Если используете Docker Compose, передайте эти переменные в контейнер backend. Затем перезапустите сервисы:

```bash
docker compose -f docker-compose.yaml up -d --build
```

Частые проблемы:

- Используйте порт 587 с `SMTP_USE_TLS=true` или порт 465 с implicit SSL (если поддерживается).
- Убедитесь, что SMTP-провайдер разрешает домен отправителя (настройте SPF/DKIM в DNS).
- Проверьте логи почты в backend-контейнере при ошибках доставки.

## 9) Эксплуатация

- Логи: `docker compose logs -f`
- Перезапуск сервисов: `docker compose restart`
- Проверка Nginx: `sudo nginx -t && sudo systemctl reload nginx`
